# 录音、视频与附件备份验收

本地 ZIP 与 WebDAV 共用 `DataArchiveService`。备份覆盖封面、图片、录音、视频、附件、数据库三张表和新建草稿；正文及草稿的媒体引用在导入时绑定到当前安装目录。

恢复先在 documents 内的隔离目录解压并校验 CRC、加密认证码、载荷版本、表结构和重复记录。历史连接未开启外键时，删除标签或日记可能留下悬空关联；这些旧备份可以正常恢复，保留全部日记、标签、媒体及有效绑定，不再因为已不存在的关联端点拒绝整包。删除标签和彻底删除日记也会显式清理绑定，不依赖外键开关。明确的空表 `[]` 可以正常导入，缺失或错误类型的表不能按空库覆盖。校验完成后，在数据库事务内换入媒体和设置；写入失败会恢复原目录、原设置及通知状态。目录移动失败按逆序回滚；回滚本身失败时保留暂存文件并报告路径。

普通和加密恢复都按最多 64 KiB 读取媒体。加密导出使用流式 WinZip AES-256、STORE 和 ZIP64，避免单个视频的加密缓冲，并兼容旧版 archive 导入。采用 STORE 的加密 JSON 不再压缩，纯文字备份体积可能比旧版大。已有普通 ZIP、AES AE-1/AE-2 和传统 ZIP 密码包均有兼容验证。

Android 与 iOS 保存备份只向原生传递文件路径。iOS 在后台准备独立文件副本，通过系统“文件”面板导出；取消、错误和关闭面板都保留调用方源文件并结束等待。

## 自动验证

在仓库根目录运行：

```sh
flutter test --no-pub
flutter analyze --no-pub --no-fatal-infos
```

回归测试覆盖正常和加密的混合媒体 WebDAV 往返、回收站与草稿、中文/空格/百分号/连续点文件名、草稿封面与时间胶囊、错误密码、CRC 或认证码损坏、缺失或坏表、重复日记标识、历史悬空关联的兼容恢复、外键开关下的数据与绑定保留、数据库和设置写入失败、目录换入及回滚失败、并发备份、空附件、ZIP64 与旧解码器兼容。源码字符串断言改由字段往返及实际 IO 行为验证。

旧备份兼容修复还在隔离内存数据库中验证了手机上的五份真实历史备份，日记和标签计数、标题/正文纯文本/metadata/时间字段校验值均与备份一致；真实个人数据不加入仓库测试资源，原 ZIP 未修改。

Linux Dart 进程的 96 MiB 视频包测量：普通恢复额外峰值内存约 1.7 MiB（修复前约 95 MiB）；流式加密导出额外峰值约 32 MiB。后者包含 Dart VM 的加密运算和垃圾回收堆开销，文件始终按固定块读取；这些数字不能代表手机整应用占用。

## 真机检查清单

明暗主题各执行一次，使用测试日记和独立测试备份，避免覆盖实际日记。

| 触发步骤 | 预期结果 |
| --- | --- |
| 创建含录音、视频及同名 PDF 附件的日记，保留一个媒体草稿；导出普通及带密码备份，再在另一测试安装恢复。 | 文件可播放或打开，内容字节、显示名称、录音时长/波形、草稿和路径正确；同名附件互不覆盖。 |
| 将文件命名为 `报告 100%..pdf` 和 `旅程..mp4`，完成备份往返。 | 恢复成功后文件存在，正文和草稿可使用，连续点不被当作目录穿越。 |
| 导入错误密码、无效表结构或损坏媒体条目的备份。 | 提示失败；原日记、设置、草稿及全部媒体保持原样，随后正常备份仍可导入。 |
| 对较大的视频执行普通及加密备份、恢复，观察等待动画。 | 操作有等待反馈，媒体没有整包传入 Dart/原生通道，完成后可以访问；中途空间或文件写入失败能保留原数据。 |
| iOS 导出备份，在“文件”面板保存到本机及 iCloud Drive；再测试取消、下滑关闭和重复点击。 | 保存成功文件名正确；取消/关闭结束等待；重复操作不会并发打开多个面板；临时副本不残留，原源文件可供重试。 |
| Android 使用系统保存面板导出并取消一次，再正常导出。 | 原有 SAF 流式保存正常，取消不会损坏源备份。 |

当前环境是 Linux，iOS 原生代码已核对 Flutter 通道注册、Xcode 源文件引用及系统 API；无法在此运行 Xcode 编译或 iOS 真机面板验收。
