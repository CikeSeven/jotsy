# 日历页面设计方案（上历下表）

## 1. 页面布局（Layout）

为了保证良好的用户体验，采用经典的“上历下表（Split View）”垂直布局。

### 1.1 顶部导航栏（AppBar）

- 左侧/中间显示当前年月（示例：`2026年3月`）。
- 右侧放置“回到今天”快捷图标，便于用户翻阅历史后快速回到当前日期。

### 1.2 上半部分：月历视图（Month Calendar）

- 使用全宽标准网格，周一至周日排列。
- 日期视觉状态增强，不仅展示数字。
- 若当天有日记，日期下方展示小圆点（Dot Indicator）。
- 若支持情绪追踪，可将圆点替换为当天心情 Emoji。
- 或使用日期背景颜色深浅形成“情绪热力图”（类似 GitHub 提交热力图）。

### 1.3 下半部分：选中日期的日记列表（Selected Day's Entries）

- 点击日历任意日期后，下方区域立即展示该日期日记列表。
- 展示方式可为平滑滑出，或直接刷新列表内容。

### 1.4 空状态（Empty State）

- 当选中日期没有日记时，展示插画或引导文案。
- 推荐文案：`这一天很安静，没有任何记录。`
- 同时提供一个“补写日记”按钮。

### 1.5 悬浮按钮（FAB）

- 右下角常驻 `+` 按钮。
- 点击后默认以“当前选中日期”创建新日记，不强制使用“今天”。

---

## 2. 具体功能（Features）

### 2.1 日期联动过滤

- 用户点击日历任意一天时，下方日记列表立即根据该日期刷新。
- 列表数据基于 Drift + SQLite 查询。

### 2.2 按月懒加载（Lazy Loading）

- 滑动切换月份时，仅加载当前月份的日记元数据用于日历打点。
- 避免一次性加载多年数据导致内存占用过高或卡顿。

### 2.3 补写与回顾

- 允许用户点击过去月份的空白日期，直接补写对应日期日记。
- 历史回顾场景需与当前创建链路保持一致。

### 2.4 手势支持

- 支持左右滑动平滑切换月份。
- 支持上下滑动将月历折叠为“周历（Week View）”。
- 折叠后为下方日记列表提供更大阅读空间。

---

## 3. 交互目标（UX Goal）

- 让“找某一天写了什么”和“补写某一天”都能快速完成。
- 降低历史翻阅成本，提升记录连续性与回顾效率。
- 在保持信息密度的同时，避免页面拥挤和操作负担。
