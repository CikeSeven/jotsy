## 当前实现

`test-shards` 将 `git ls-files` 的有序 `test/*_test.dart` 列表轮流分给 4 个
runner，每个文件完整运行一次。分片索引从 0 开始，片数取 `strategy.job-total`，
不需要维护测试目录白名单。新增测试提交到 Git 后会自动参与分片。

当前锁定的 test_core 的 `--total-shards` 在 suite 加载后才筛选其中的测试，
直接使用它会让每个 runner 仍编译所有测试文件，因此在启动 Flutter 前分配文件。
分片保留原有的测试进程并发数，避免同时修改两个性能变量。

每片上传独立 LCOV，`Tests` job 等待所有分片成功，检查报告数量后合并，保留
原有的全量覆盖率摘要和 `coverage-lcov` 附件。合并按源文件、行号累加命中次数，
重新计算 LF / LH；直接拼接报告或平均百分比会重复计算共享代码。
`merge_lcov.dart` 只支持当前 Flutter 默认的行覆盖率，遇到函数或分支覆盖率
记录会失败，后续启用这些采集选项时须同步扩展合并逻辑。

按现有各 job 耗时，测试分片后整体预计由约 6～8 分钟的 Android job 决定，
加上波动可先以 7～9 分钟为目标。这是估算，需在 GitHub 上运行后再核对各片
耗时和完整工作流耗时；runner 排队与测试文件负载不均也会影响结果。

## 测试清理范围

日记本、模板、纪念日、卡片样式和预览样式原来为每个源码文件注册一个重复的
规则测试。现在统一到 `test/ui/source_rules_test.dart`，每个源码文件只读一次，
每条规则只注册一个用例，失败时列出所有违规文件与行号。原有 241 个源码文件
仍全部包含在检查范围内，控制器防抖计时的例外也保留。日历与网盘界面的相同
规则一并复用。删除了四个功能各自重复维护的规则测试文件。

| 删除或合并的检查 | 保留的验证 |
| --- | --- |
| 各模块重复的 UI 规则与任意文件数量断言 | 共用源码规则；每个目录须非空，显式文件必须可读取 |
| 编辑页是否含某段 PopScope 源码 | 已有录音面板交互测试直接检查开关面板前后编辑器 Element 不变 |
| 网盘表单是否用了指定的图标构建器 | 已有 widget 测试测量四个图标的横向中心是否对齐 |
| 关于页与网盘界面的局部 ARB key / metadata 检查 | `tool/check_arb.dart` 对中英文全部 2283 条文案检查，编译同时验证生成 getter |
| 仅检查目录存在、源码文件数量或特定注释文字的用例 | 对应功能与架构规则检查；不再固定文件组织或注释写法 |

全应用菜单约束、渐变白名单、禁止导入完整高亮库、代码块编辑钩子等独有规则
继续保留。数据库迁移、备份恢复、私密日记、录音、明暗主题和窄屏矩阵的行为
测试均保留。测试数量减少不能直接换算为同等比例的加速，主要提速仍来自文件
分片；清理避免继续累积重复维护与执行的成本。

## 后续优化的优先级

先对比同一 Flutter 版本下各分片的耗时。若分片负载不均，再根据测试报告调整
分配方式。Android 构建成为瓶颈后，再评估 NDK 安装和 Gradle 构建缓存；目前
日志中仍会安装 NDK，Gradle 依赖缓存命中也不代表项目编译结果被缓存。

暂不缓存整个 `.dart_tool` 或 `build/test_cache`：本地这些目录已达数 GB，包含
与 SDK、路径及源码相关的产物，恢复与上传成本、失效条件都需要单独测量。
全量测试、覆盖率、生成代码检查与 release 构建均保留。

## 本地验证

删减前基线：全量带覆盖率测试 3498 项通过，2 项手动基准跳过。删减后按文件
分成 4 片（108 / 108 / 107 / 107 个文件），合计 3253 项通过、2 项跳过，
净减少 245 个用例。对比前后测试事件清单，所有行为测试均保留；减少的都是
源码检查用例，其中 256 项被删除或合并，新增或重命名的源码检查为 11 项。

四片覆盖率经 `tool/merge_lcov.dart` 合并后，与删减前基线逐行对比：前后均为
57027 / 68486 行，已覆盖的行集合完全相同（此处包含生成代码）。
本地顺序验证的每片耗时约 78～94 秒，用于检查分片和合并逻辑；本地硬件与
缓存情况不同，不能作为 GitHub runner 的提速实测。

格式检查、`flutter analyze`、ARB 检查与 actionlint 通过。分片脚本验证覆盖
全部测试文件且无重复，空分片和 Flutter 非零退出码会失败。合并逻辑还使用
线上真实 LCOV 检查共享行去重与命中累加；汇总门禁只接受所有分片成功，缺少
报告或含空报告都会失败。
