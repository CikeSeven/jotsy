# 代码块语言识别与高亮

原实现用 highlight.js 对 22 种语言逐个解析，要求相关度至少 6、第一名领先至少 2。
短代码常常达不到这个分数，JavaScript 与 TypeScript 的共同语法也容易打平，
导致返回“无法识别”，正文随之没有高亮。22 种语言的短代码回归样例中，旧实现有 14 种识别失败。

识别现在由 `DiaryCodeLanguageDetector` 做有界的语法特征扫描：完整 JSON 直接确认，
其他语言按特征计分，字符串和注释中的示例代码不参与判断。最多向前检查 20000 字符，
跳过开头的空白与 C 风格说明注释，再取最多 2000 字符的样本。识别不初始化高亮引擎。
这能覆盖短片段与正在输入的声明；只有共同语法的片段仍存在歧义，可在代码块面板手选语言。

`DiaryCodeLanguageTracker` 继续负责每个控制器的共享结果。首次显示时同步识别，
后续输入沿用现有语言，停手 600ms 后合并识别一次；高亮、标题栏与工具栏共用结果。
选择纯文本、指定语言、关闭自动识别、删除代码块或离开编辑器时丢弃多余的待处理任务。

高亮仍只使用现有的 22 种语法定义。对于 Dart、Python、JavaScript、TypeScript 和 JSON
的长代码，局部编辑可只解析改动行及前后邻行，再平移其余区间。旧快照必须来自完整解析，
旧窗口单独解析也必须与完整结果一致；跨行注释、模板字符串、声明包装、续行或未闭合引号
都会使这条加速路径回退到完整解析。非法记号仍逐行容错。JS/TS 的私有字段 `#field`
仅在解析副本中用等长字符兼容，日记内容和复制文本保持原样。

高亮缓存保留至多 48 份，并按约 1MiB 的原文和区间权重预算淘汰；这不是进程堆内存上限。
识别缓存最多保留 128 份、32768 个 UTF-16 code unit。超过 20000 字符或 600 行的块
在拼接正文前就按 Quill 的结构尺寸跳过，保持纯文本显示。

导出 PDF、Word 与网页时经 `DiaryExportCodeTheme` 复用同一个高亮器、同样的上限与配色。
导出没有编辑器控制器，未指定语言的块按“自动识别语言”开关直接整块识别一次，不经防抖。

## 验证

短代码语料覆盖全部 22 种语言，另有普通中英文、注释/字符串里的语言特征、长说明注释、
相近语言和不完整声明的回归。增量测试用随机插入、删除、换行、引号、跨行注释和 Unicode
编辑，与每次重新完整解析的区间逐项比较。编辑器测试在浅色与深色主题下验证自动结果刷新。

可复现的界面检查：

1. 新建自动识别的代码块，输入 `def greet(name):`，停手后显示 Python，`def` 着色。
2. 替换为 `const count: number = 42;`，停手后显示 TypeScript，关键字与数字着色。
3. 持续编辑已识别的代码，语言标签保持稳定；输入跨行注释或模板字符串后检查整段颜色。
4. 切为纯文本、关闭自动识别后，自动着色停止；手选语言仍按所选语法着色。
5. 在浅色和深色主题重复上述步骤；长代码块编辑时检查光标、选区与中文/表情偏移。

本机基准命令：

```sh
flutter test test/performance/diary_code_highlighting_benchmark_test.dart \
  --dart-define=PERFORMANCE_BENCHMARK=true --reporter expanded
```

该基准报告首次识别、未缓存识别、缓存命中与约 1.8 万字符代码的局部编辑时间。
它用于同一台机器的改动前后对比，不设置不稳定的墙钟时间门禁，也不代表手机功耗测量。

2026-10-20 同机 Flutter 测试 VM 的前后结果（单位 ms）：

| 场景 | 修改前 p50 / p95 | 修改后 p50 / p95 |
| --- | --- | --- |
| 未缓存的短代码识别 | 0.485 / 0.856 | 0.057 / 0.083 |
| 18450 字符代码的单行局部编辑高亮 | 12.062 / 13.219 | 0.200 / 3.330 |

验证结果：全量 `flutter test` 3231 项通过，2 项手动基准默认跳过；上述代码块基准
已单独启用并通过。`dart format` 检查 1299 个文件无变化，`flutter analyze` 无问题。
