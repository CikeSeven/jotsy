# 探索页面设计规范（Card UI + 情感回顾优先）

## 1. 页面定位与设计原则

探索页定位为“回顾与洞察中心”，不是二级设置页，也不是纯统计后台。整体目标是帮助用户从感性回忆自然过渡到理性分析，形成持续记录动力。

### 1.1 视觉风格

- 使用 Card UI，但去除厚重阴影。
- 卡片之间通过极细边框或清淡背景色分层，不依赖强投影。
- 与日记列表页、日历页保持一致的轻呼吸感和留白节奏。
- 内容优先，装饰克制，避免“报表化”压迫感。

### 1.2 交互动线

- 页面采用垂直瀑布流滚动（从上到下）。
- 信息层级固定为：
  1. 轻量数据看板
  2. 那年今日（核心情感模块）
  3. 情绪与精力趋势
  4. 标签云
  5. 媒体画廊
- 模块内允许局部横向滑动（如媒体画廊），但不打断主纵向浏览节奏。

---

## 2. 顶部模块：轻量级数据看板（Dashboard Stats）

### 2.1 UI 布局

- 位于页面最顶部，横向排列 3 个紧凑数据块。
- 单个数据块由“主数字 + 极小辅助文案（可选微图标）”组成。
- 整体视觉弱化，不与下方“那年今日”争抢焦点。

### 2.2 指标定义

- 总计记录：优先展示总篇数；若后续需要可扩展切换为总记录天数。
- 连续打卡（Streaks）：当前连续写日记天数，可配小火焰图标。
- 本月字数：当前自然月累计正文字符/词数（实现时统一口径）。

### 2.3 数据来源

- 基于本地日记库聚合计算。
- 仅统计“未删除”日记；归档日记默认计入（与日历统计口径一致）。

---

## 3. 核心情感模块：那年今日（On This Day / Memories）

### 3.1 UI 布局

- 作为首屏视觉重心，占据较大宽卡片区域。
- 顶部展示时间标签：如“1年前的今天”或“2023年3月12日”。
- 主体展示：标题、正文摘要、首图缩略图（若存在）。

### 3.2 功能逻辑

- 主逻辑：查询历史年份中“同月同日”的日记并展示。
- 推荐展示策略：优先最近年份；若多条可提供轻量切换入口（后续增强）。

### 3.3 空状态备用逻辑

- 若无“同月同日”历史记录，进入随机漫游备用逻辑：
  1. 优先展示星标/收藏日记（若能力存在）。
  2. 若无星标能力或无可用数据，展示“每日写作引导提示（Prompt）”。
- 推荐文案示例：`今天发生了什么意料之外的好事？`

### 3.4 数据来源

- 日记基础字段：标题、正文摘要、封面/首图、创建时间。
- 收藏/星标字段若当前版本不存在，按降级策略执行。

---

## 4. 洞察模块：情绪与精力趋势（Mood & Energy Insights）

### 4.1 UI 布局

- 采用两个子卡片上下排列（首版），或后续支持 Tab 切换。
- 子卡片 A：情绪趋势（30 天）。
- 子卡片 B：精力趋势（7 天）。

### 4.2 情绪趋势（30 天）

- 可选表现形式：
  - 简单条形图（情绪权重均值）。
  - Year in Pixels 风格小方块网格（推荐，轻量直观）。
- 每日数据优先取当日情绪均值（已有多篇日记时做聚合）。

### 4.3 精力趋势（7 天）

- 使用平滑折线图展示 1-5 范围的连续精力值变化。
- 当天多篇日记时采用均值，缺失日期允许断点或空值补位（实现时固定一种口径）。

### 4.4 关联洞察（增强能力）

- 从天气、标签、情绪、精力中做轻量交叉分析，输出一句话洞察。
- 示例：
  - `数据表明，当天气为晴天时，你的平均精力值更高。`
  - `带有 #工作 标签的日子里，你更常记录焦虑情绪。`
- 首版（MVP）可先不实现自动洞察，仅保留文档入口与字段准备。

### 4.5 数据来源

- 优先读取 metadata 中已存在字段：`moodEmoji`、`energyLevel`、`weather`、`weatherIconCode`、标签信息。
- 缺失字段不报错，按“无数据态”降级展示。

---

## 5. 组织模块：标签云与分类（Tag Cloud）

### 5.1 UI 布局

- 采用紧凑药丸 Chips 排列，支持自动换行。
- 标签视觉权重随使用频率变化：
  - 字体大小变化或
  - 背景深浅变化（两者二选一，避免视觉噪音）。

### 5.2 功能逻辑

- 点击标签后跳转到“带该标签的日记过滤列表”。
- 不在探索页内直接展开长列表，保持探索页信息密度稳定。

### 5.3 数据来源

- 使用标签表与日记标签关联表聚合得到频次。
- 统计口径同样以“未删除日记”为准。

---

## 6. 底部模块：媒体画廊（Media Gallery / Attachments）

### 6.1 UI 布局

- 展示形式二选一（实现时确定）：
  - 横向滑动 Carousel（推荐）。
  - 2x2 照片网格。
- 纯图片展示，尽量不叠加文字，弱化干扰。

### 6.2 功能逻辑

- 展示近期日记中的图片资源（封面与正文图片均可纳入）。
- 点击缩略图可进入对应日记预览页（或图片查看器，后续增强）。

### 6.3 数据来源

- 日记封面字段 + 正文富文本内图片资源提取结果。
- 已删除日记的媒体不参与展示。

---

## 7. 状态与交互规范

### 7.1 页面状态

- 加载中：使用轻量骨架或最小加载占位，不覆盖整页。
- 空状态：按模块级空状态展示，不让整页“空白”。
- 异常状态：模块内就地提示，可重试，不中断其他模块渲染。

### 7.2 滚动与触达

- 主体为单一纵向滚动容器。
- 模块点击行为清晰可预期：
  - 那年今日卡片：进入对应日记预览。
  - 标签云：跳转标签过滤列表。
  - 媒体图：进入图片来源日记预览。

### 7.3 文案语气

- 语气轻快、陪伴式，不使用后台统计语气。
- 避免“失败/错误”高压词，优先引导式表达。

---

## 8. 实施优先级（MVP / 增强）

### 8.1 MVP（首版必须）

- 页面骨架与模块顺序落地。
- 顶部数据看板（3 指标）。
- 那年今日主逻辑 + 无记录备用逻辑（至少写作提示）。
- 情绪趋势与精力趋势基础图表（无关联洞察）。
- 标签云点击跳转。
- 媒体画廊基础展示。

### 8.2 增强（后续迭代）

- 那年今日多条历史切换。
- 关联性分析自动文案。
- 图片查看器增强交互。
- 统计维度与过滤条件扩展（如时间窗、标签组合筛选）。

---

## 9. 约束与默认假设

- 本规范仅用于探索页设计与实现，不涉及数据库结构变更。
- 文档术语以中文为主，保留必要英文（Card UI、Dashboard、Streaks）。
- 若“星标/收藏”能力缺失，随机漫游默认降级为“每日写作提示”。
- 首版优先保证体验闭环与性能稳定，不追求一次性全量洞察功能。
