# 从其他应用导入：格式与完整性验证

本次检查覆盖 12 类文件来源、8 类云端来源，以及共用的正文转换、媒体暂存、预检、合并写入和失败回滚。文件来源通过可控导出样本走完整导入链路；云端来源通过已有的 HTTP 协议模拟测试验证。没有使用真实账号登录厂商服务，因此不能把这些结果当成所有厂商在线接口、所有历史版本导出的兼容保证。

## 云端来源

小米、华为、OPPO、vivo、荣耀、魅族、WPS、锤子继续使用各自的只读客户端和内存登录会话。锤子便签官方没有导出，协议依据网页版与三份独立的开源导出脚本交叉核对。既有平台测试覆盖列表、详情、附件、富文本和错误映射；共用链路新增以下约束：

- 笔记 ID 为空或重复时，在下载附件前停止，避免静默覆盖或丢篇。
- 空附件、没有附件记录的正文引用、重复失败引用均计入缺失，不能写入空文件冒充成功。
- 网络、登录、限流和协议变化中止读取；可明确归因到单个文件的失败进入预览统计。
- 时间戳兼容数字字符串，拒绝无穷、越界和哨兵值；OPPO 分页期间总数变化时停止。
- 录音与视频即使共用 3GP 容器，也保留来源 MIME 指定的媒体类型；复用已暂存文件时类型保持一致。

## 完整性约束

1. 附件索引在移动源文件前建立；共享附件只暂存一次。文件名兜底必须唯一，不能悄悄选择另一个文件夹里的同名图片。
2. 解析器产生重复来源键时确定性分配后缀，不丢弃正文；原始标题、标签和必要的来源信息保留在 `metadata.import` 中。
3. 无法识别的条目、缺失媒体、仅有摘要和含不可显示片段的笔记，在预览中分别说明。所有条目都不可读时，也返回跳过原因。
4. ENEX 加密片段不在正文中展示，原始密文和解密提示保留在日记 metadata 中并随备份保存。没有密钥无法恢复明文。
5. 导入始终复用 `chooseBackupImportMode` 和 `BackupMerge`。覆盖已有日记仍需严重警告确认，其他应用导出不能覆盖本机全部数据。
6. 会话释放等待已经排队的导入事务结束；释放后的会话拒绝写入。并发准备不会互相清除存活暂存区。
7. 数据库写入失败时事务回滚，本批次媒体清除，原有数据与原始导出文件保留。

## 自动验证

在仓库根目录运行：

```sh
dart format --output=none --set-exit-if-changed lib test integration_test tool
flutter analyze --no-pub
dart run tool/check_arb.dart
flutter test --no-pub
```

关键新增用例位于 `journal_import_integrity_test.dart`、`journal_import_format_edges_test.dart`、`journal_import_media_integrity_test.dart`、`journal_import_roundtrip_test.dart`；平台与导入面板测试沿用并扩充现有用例。

## 实际文件与账号验收

1. 在原应用统计有效笔记数，导出后保留原文件。导入预览核对可导入、跳过、摘要、部分正文及缺失媒体的数量。
2. 导入后抽查中文和表情、长正文、时间、标签、归档、录音、视频和普通附件；对关键附件比对原件字节或摘要。
3. 再次导入同一文件，应识别为已存在；取消导入和取消覆盖警告都不改变本机数据。
4. 在中英文、亮暗主题及 320dp 屏宽下，确认不完整内容说明可读、面板可滚动、默认方式仍为合并，覆盖仍经过确认和倒计时。

第三方私有格式、端到端加密、损坏的原始文件以及厂商接口更新需要真实样本或账号复核。对于缺失的数据，系统提供可核对的提示和失败边界，不能自动补回原导出没有携带的内容。
