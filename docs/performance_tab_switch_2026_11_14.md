# 首页左右切页优化（2026-11-14）

基于 `fd12d71e`（PR #250 合并后）。范围是窄窗口首页的 Tab 切换（点底栏与
左右滑动），宽窗口与减少动画的行为不变。

## 问题与定位

设备：小米 13（`2211133C`，120 Hz，Impeller Vulkan），图片背景 + 玻璃卡片 +
玻璃底栏，三个 Tab（日历 / 日记 / 探索），500 篇测试日记。arm64 profile 包，
经 VM service 采集 `Flutter.Frame` 与时间线，另用 SurfaceFlinger 的上屏时间
统计真实漏掉的 vsync。

改动前两页同屏阶段（每次切页前约 24 帧）光栅均值 12.8ms、p90 19.7ms，
120 Hz 预算 8.3ms。临时加运行时开关逐项关闭后，两页同屏阶段的光栅均值：

| 关闭项 | 光栅均值（ms） |
| --- | ---: |
| 无（全开） | 11.0–12.8 |
| 景深（缩放 + 圆角 + 压暗） | 9.7 |
| 顶栏实时模糊（两页各一条） | 8.7 |
| 底栏与新建按钮的模糊 | 9.4 |
| 背景插值上面那层（整屏透明度合成） | 10.0 |
| 以上全部 | 5.1 |

光栅线程主要耗在编码与 `saveLayer`（每帧约 8 次）；Impeller 没有光栅缓存，
两整页的内容与两条顶栏的背景模糊每帧都要重新编码。另有两处 UI 线程尖峰：
PageView 默认把移出视口的页挪进保活桶、移回时再取出，`_destroyOrCacheChild`
与 `_createOrObtainChild` 各对整棵页面子树 detach + attach 一次，起步与落位
各卡 8–16ms。

## 改动

- **快照**：窄窗口切页途中，`HomeTabDepth` 在卡片开始移动的那一帧把“卡片
  自带的底 + 页面”拍成一张位图，之后逐帧只画一笔带圆角的 `drawRRect`（位图
  作着色器），不建任何图层。拍照的临时图层按卡片落在正中的位置挂进图层树，
  内容玻璃的取样（FollowerLayer）对齐静止位置；整页移出视口即释放。拍不了
  （平台视图）时退回实时的变换 + 裁切。
- **卡片自带区域背景**（经产品确认的外观变化）：有背景图时卡片连同本区域的
  壁纸一起缩放、移动（`AppPagedAreaBackground`，与背景层同一组图层），缝隙
  一律铺舞台色。快照里的玻璃只能对着卡片自己里面的东西取样，这样在卡片里
  始终正确，静止时与实时绘制一致。背景层此时被盖住，不再画插值层
  （`occludedWhileMoving`）；减少动画时各区画面相同也只画一层。
- **只对显示过的 Tab 拍快照**：第一次切到的页在起步那一帧才创建，数据（探索
  统计、日历当月汇总）与入场动画都还没到，拍下来是一张空页，会冻结整个切页
  并在放开时突然出现内容（装机后录屏发现）。这一次照常实时绘制、ticker 照常
  跑，落定后才记为显示过；启动页一开始就算显示过。
- **落位后保持**：快照阶段 GPU 降频，刚落位就恢复实时绘制，头几帧要等 GPU
  爬频（13–15ms）。落位后继续画快照，等“没有动画再请求下一帧”、手指按到页面
  上、回到顶部或满 400ms 再换回实时；途中与保持期间各页 ticker 暂停，内容
  不会在落位时跳一下。
- **PageView**：缓存区覆盖全部 Tab，页面一直留在子列表里，不再进出保活桶；
  离屏页经 `ExcludeSemantics` 排除，页面仍在第一次出现在可见区间时才创建。
  子页不另包重绘边界：重绘按深度从深到浅进行，单独重绘的子页拍照时祖先图层
  还在上一帧的位置，快照里的玻璃取样会错开约一帧的位移（真机实测 46 物理
  像素，落位放开时可见一闪）。

## 结果

同机、同数据、同脚本（每轮日记 → 探索 → 日记 → 日历 → 日记）：

| 场景 | 指标 | 改动前 | 改动后 |
| --- | --- | ---: | ---: |
| 左右滑动 | Flutter 超预算帧 | 30.5% | 3.6% |
| 左右滑动 | SurfaceFlinger 漏 vsync | 22.6% | 3.7% |
| 点底栏 | Flutter 超预算帧 | 34.5% | 5.9% |
| 点底栏 | SurfaceFlinger 漏 vsync | 21.3% | 5.7% |
| 两页同屏 | 光栅均值 / p90（ms） | 12.8 / 19.7 | 4.5 / 7.6 |
| 全程 | UI 线程超 8.3ms 的帧 | 17 / 1051 | 0 / 1233 |
| 冷启动首访各 Tab | Flutter 超预算帧 | 40.4% | 见下文 |

保持期截图与放开后的实时截图逐像素比较（每个 Tab 往返 6 次）：最大差 1 个
色阶，没有像素差超过 2。

剩余的慢帧：起步拍两张快照的一到两帧（GPU 从空闲的低频起步渲染两页离屏
图）；放开快照那一帧（Impeller 的渲染目标缓存只保留上一帧用过的，需要重新
分配，约 25ms 编码，此时画面静止）。首次切到探索后、数据算完那一帧约 60–70ms
（改动前同样存在，属于探索页首次加载，不在切页机制里）。

## UI 复现检查

| 操作 | 预期 |
| --- | --- |
| 冷启动后第一次切到日历、探索 | 内容与数字滚动在滑动途中照常出现，落位后不再突然冒出内容 |
| 有背景图时慢慢左右拖动并停在半途（亮 / 暗主题） | 两页各自连同壁纸缩成圆角卡片，缝隙是舞台色；卡片里的玻璃卡片、顶栏毛玻璃与卡片自己的壁纸对齐 |
| 无背景图时同样拖动 | 与改动前相同：卡片之间舞台色，页面不透明 |
| 点底栏切页，落位后立即向上滚动列表 | 落位不跳、不闪；按下后列表立即可滚动 |
| 从日历点到探索（跨页折叠） | 只滑一页，中间页不出现 |
| 切页途中再点别的 Tab、或用手指接住 | 带着速度改道 / 停住，画面不卡 |
| 开启减少动画后拖动 | 页面直接平移，背景固定并按位置插值，没有卡片 |
| 宽窗口（≥ 600）切换侧边栏 | 与改动前相同的入场效果 |
| 各区域设不同背景后切页 | 每张卡片带自己区域的背景，落位后背景层是目标区域的 |

## 复现命令

```sh
flutter build apk --profile --split-per-abi --target-platform android-arm64 \
  --build-number 27
adb -s <serial> install -r build/app/outputs/flutter-apk/app-arm64-v8a-profile.apk
```

采样脚本（VM service 帧事件、时间线、SurfaceFlinger 延迟表）保存在会话的
临时目录，不入库；方法与 [2026-11-14 滚动优化](performance_scroll_2026_11_14.md)
相同。
