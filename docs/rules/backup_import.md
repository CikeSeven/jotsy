# 导入 / 恢复与网盘备份

> 从 `AGENTS.md` 拆出的专题约束，与 `AGENTS.md` 同等效力（必须 / 禁止 / 例外）。改动本主题的代码前先读本文件；本主题新增或修改的规则写在这里，不写回 `AGENTS.md`。界面规格见 DESIGN.md §5.30；网盘备份说明见 `docs/cloud_backup.md`。

- 必须：数据导入/恢复入口统一经 `chooseBackupImportMode`（`DataArchiveService.inspectZip` 只读预检 → 选择合并或覆盖），会改写本机已有数据的方式必须经 `showBackupOverwriteWarningDialog` 严重警告确认；禁止新增不经警告直接覆盖本机数据的入口。其他日记应用的导出经 `JournalImportService.prepare` 解析为备份载荷并只读预检，同样走 `chooseBackupImportMode`，写入复用 `BackupMerge`；新增来源只加 `journal_import_<来源>.dart` 解析器，不另建写库路径。解析器（含云端平台客户端）只把来源里的日记本 / 笔记本 / 文件夹名原样报告在 `JournalImportEntry.notebooks`，禁止自行转成标签；落成日记本、标签还是两者只由 `JournalImportFolderMode`（notebooks / tags / both）在 `buildJournalImportPayload` 里决定，用户在导入方式面板的“原来的日记本 / 文件夹”一节（`BackupImportFolderChoice`）选择，选择只记在内存 `journalImportFolderModeProvider`、不加设置键；落成日记本经 `JournalImportNotebookBuilder`，先按确定性 id（`journalImportNotebookId`）再按同名手动日记本复用，复用时载荷里放本机那一行的原样拷贝（合并并覆盖不得重置用户改过的图标、封面与章节），都没有才新建；名称落地时被规整或截断的，原名记在日记 metadata 的 `import.originalNotebooks`（与 `originalTags` 并列）。导入正文的文字色、背景色、字号与对齐只经 `journal_import_style.dart` 换算（颜色统一 `#AARRGGBB`、来源默认墨色不导入、字号只写 small / large / huge 三档、对齐只写 center / right / justify），分隔线一律写成 `diaryDividerEmbed`（`divider_embed_codec.dart`，由共用 `DiaryEditor` 的分隔线块渲染、导出为各格式的分隔线），禁止各解析器自拼颜色字符串或绝对字号；标题保留 1–6 级，上下标只写行内 `script`（super / sub）；结构块只经 `JournalBlockWriter.node` 写入（折叠块的标题行用块属性 `toggle` + `collapsed`，内容按 `indent` 挂在它下面），禁止解析器自行拼树；表格只在规整时（无合并单元格、各行格数相同、不超过 12 列 / 200 行、格内只有行内格式）写成表格块（`journal_import_html_table.dart` / `journal_import_markdown_table.dart`），否则展开为文字，试写格子时禁止调用媒体 / 附件解析器；8 位十六进制颜色按来源约定区分 CSS `#RRGGBBAA` 与 Android `#AARRGGBB`（`journalArgbToCss`）。手机厂商与 WPS 的云端笔记经 `CloudNotesLoginPage` 在官方网页登录、`JournalImportService.prepareCloud` 读取（平台客户端为 `journal_import_cloud_<平台>.dart`，在 `cloudNotePlatforms` 登记），只做读取；登录 Cookie 只存在于本次导入的内存与网页视图中，登录前与导入结束后都必须清除，禁止落盘或用于读取以外的请求。平台客户端整篇不导入某篇笔记时（回收站中的除外）必须按原因记入 `CloudReadIssues`（加密 / 专有类型 / 无法识别），由导入预览逐项说明，禁止静默丢弃；参考实现「笔记互迁」是迁移工具，为“原笔记留在云端”而整篇拒绝的内容，导入时尽量降级保留（未知区块留文字、正文读不到用摘要并计入 `summaryOnly`），不照搬整篇拒绝。
- 必须：网盘备份（WebDAV、S3 兼容对象存储、授权类网盘）统一经 `CloudBackupService` 编排、`CloudBackupRemote` 访问远程，恢复同样走 `chooseBackupImportMode`；备份位置与凭据只存于 `CloudBackupSettingsService`（单个 JSON 偏好键 `app.cloud_backup.targets`，逐条容错解析，**不随备份导出**），禁止另加零散的连接/令牌设置键。授权类网盘的应用密钥只经 `CloudBackupAppKeys`（`--dart-define` 注入）读取，禁止写进仓库；授权只用系统账号授权（Android 上 Google Drive 经 Play 服务，不可用时回落设备码）、设备码或在系统浏览器授权后粘贴授权码（Google、Dropbox 禁止内嵌网页授权），刷新后的令牌必须立即落盘（多家会轮换刷新令牌）。新增网盘只加 `cloud_backup_<平台>.dart`（实现 `CloudDriveProvider`）并在 `cloud_backup_drives.dart` 登记；新增 WebDAV/S3 服务只在 `cloud_backup_presets.dart` 加预设、在 `cloud_backup_labels.dart` 加名称与填写说明。上传与下载一律流式读写文件，禁止整包读入内存。“备份”主按钮为增量备份，完整 ZIP 仍可上传、列出与恢复：增量备份只经 `CloudIncrementalBackup` / `CloudIncrementalRestore`（`cloud_backup_incremental*.dart`）编排，远端文件平铺在备份目录（媒体包 `.pack`、快照 `.snap`、索引 `.idx`，都不以 `.zip` 结尾，旧版看不到），经 `CloudBackupRemote.listFiles` 列出（`list` 一律为 `cloudZipBackupsOf(listFiles())`）；媒体按 sha256 去重打包（约 32 MiB 一个，省请求次数），写入顺序为包 → 快照 → 索引（索引是提交标记），快照载荷刻意不叫 `backup_data.json`（禁止改回：旧版与本地导入会把没有媒体的快照当完整备份覆盖恢复）；网盘来的索引必须严格校验哈希、包名与媒体键（`isValidIncrementalMediaKey`）。恢复只经 `DataArchiveService.importFromPreparedStaging`：本机已有同样内容的媒体复制（禁止移动，覆盖失败的回滚依赖原目录），只下载缺少内容所在的包，包缺失或内容与哈希不符整次放弃。清理只经纯函数 `planIncrementalPrune`（保留份数、按链回收、24 小时宽限、读不出的链不动、每次最多删 100 个）。一条链共用一个密码，第一次备份设定后与链 id 一起存在位置的 `options`（`CloudBackupOptions`，与连接配置 `config` 分开，表单保存与重新授权不能冲掉它，只经 `CloudBackupSettingsService.updateOptions` 改写），本机状态（媒体哈希缓存、续传日志、索引缓存、自动备份结果）只在 `<数据根>/cloud_backup_state/`（`CloudBackupLocalState`），禁止放进偏好或备份。同一位置的增量操作经服务的锁排队。自动备份按位置开启（默认关，须先手动成功备份一次），只经 `CloudBackupAutoScheduler`（冷启动、切到后台、前台每小时）→ `CloudBackupService.runAutoBackup`，是否该备份只经 `isCloudAutoBackupDue`；全程静默（不弹窗、不弹提示条），新增内容超过 50 MB 时留给手动备份，结果显示在位置列表与位置页。说明见 docs/cloud_backup.md。
