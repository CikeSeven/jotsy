# 局域网同步

> 从 `AGENTS.md` 拆出的专题约束，与 `AGENTS.md` 同等效力（必须 / 禁止 / 例外）。改动本主题的代码前先读本文件；本主题新增或修改的规则写在这里，不写回 `AGENTS.md`。界面规格见 DESIGN.md §5.28；规格与协议见 `docs/lan_sync.md`。

- 必须：局域网同步（设置 → 数据与隐私 → 局域网同步，规格与协议见 `docs/lan_sync.md`，界面见 DESIGN.md §5.28）在已配对设备之间双向合并全部数据（日记含回收站、标签、日记本含成员 / 书序 / 层级、留言、模板、纪念日、这天的心情、托管媒体），**同步不是导入**：禁止经 `chooseBackupImportMode` / `BackupMerge` 或调用会改写 `updatedAt`、清掉归档 / 删除标记的 UI 写库函数。合并按 `docs/lan_sync.md` §4 逐分面判定祖先（历史哈希），只在真冲突时按规则取舍；禁止悄悄丢掉本机的编辑：正文两边都改过时另存冲突副本（id 由数据决定），副本继承败方的标签、日记本成员、胶囊、归档、回收站与置顶分面（私密内容不因副本出现在全部日记，未解封的胶囊不提前解封）；删除只在对方墓碑覆盖时传播，删除超过保护阈值与首次同步 / 覆盖恢复后的无祖先冲突必须经用户确认（删除保护默认“保留，并恢复到另一台”，以哪边为准默认“保留两份”），自动同步遇到确认一律中止、不写入并标记“需要确认”。规划器（`sync_planner*.dart`、`sync_plan*.dart`）必须保持纯函数（不碰数据库、文件、时钟与随机数，按 `SyncKey` 排序遍历）；同步写库只经 `SyncApplier` → `_AppDatabaseSyncWrites` / `_AppDatabaseSyncOrder`：按原值写列（不刷新时间）、事务开始时逐条核对前置条件（不符跳过、下次再处理）、单个 Drift 事务、媒体在开事务前暂存校验就位（不覆盖另一份文件，改键并通知对方），写入后经 `recordAppliedState(after, historySeenAt:)` 原样传入计划的 `historySeenAt`（漏传多台设备不收敛）。设备绑定的状态（身份私钥、`store.json` 里的配对设备与偏好、检查点 / 历史 / 墓碑 / 改名 / 哈希缓存 / 媒体索引、同步记录）只存于不随备份的 `stateDir`（Android `noBackupFilesDir/lan_sync/`，桌面应用支持目录 `lan_sync/`，经 `lanSyncStateDirectory`），禁止放进 SharedPreferences、备份或另加设置键；引擎各类只经构造参数拿数据库、数据根、`stateDir` 与 `SettingsService`，生产目录只在 `createAppLanSyncService`（`lib/ui/lan_sync/providers/lan_sync_engine_assembly.dart`）解析。不同步：草稿、导入的字体文件、心情选项、本机偏好（不随备份导出的键）、网盘凭据与应用锁开关、AI 服务商与密钥、AI 用量与 AI 记录（对话 / 回应 / 回顾）；设置只在两端都开启“同步设置”时同步（键集合取自 `BackupSettings.capture`，经 `BackupSettings.restore(clearLegacyDraft: false)` 只应用变化的键），但标签顺序与数据类功能开关（日记本、纪念日、日记模板、时间胶囊、留言）在 prefs 记录里始终同步：标签顺序按列表合并，数据类开关**只同步开启**（对方关掉不会关掉本机的，禁止改成双向——关闭日记本在有私密本子时必须先确认，同步里弹不了）；界面类开关（日历 Tab、探索 Tab、侧滑归档、AI 助手）仍随“同步设置”。本功能不提升数据库 schema、不新增 SharedPreferences 键。覆盖恢复成功后经 `DataArchiveService.replacedAllListeners` 通知引擎删掉同步状态并给已配对设备置 `restoredPending`。并发：握着可编辑内存副本、整份写回的页面与面板（编辑 / 发布页的 `DebouncedAutoSaveController`、纪念日 / 日记本编辑页的 `EditingSessionBlocker`、模板编辑页、留言面板、目录页与日记本管理页拖动排序的 `ReorderEditingGuard`）必须登记为 `EditingSessionRegistry` 的阻塞者——登记期间不发起同步、对方请求以忙碌拒绝；常驻的自动保存（预览页待办）登记为冲刷者；带撤销按钮的提示条经 `showTrackedSnackBar` 自动登记撤销窗口，同步写入前等它关闭（超时即推迟，不写）；写入后 `dataReplaced` 由 `syncedDataRefreshProvider` 失效一次性读取的 provider，新增一次性读取同步数据的 provider 必须加进它的清单（`.watch()` 实时查询与设置 Notifier 不必）。网络：引擎随应用启动（`NodeDiaryApp` 常驻监听 `lanSyncControllerProvider`，provider 挂 `AppLifecycleListener` 跟随前后台），但没有已配对设备时服务端与发现只在同步页打开期间运行，有已配对设备时只在前台运行，后台一律停掉（不做后台常驻）；“可被发现”关闭时发现只听不发；传入的配对只在同步页打开时接受。配对只经核对码（握手带承诺，双方确认）或一次性二维码令牌（2 分钟、扫过即失效）；本机有应用锁或上锁日记本且能上锁（系统验证或应用密码）时，确认配对前先经 `IdentityVerifier` 验证（`LanSyncPairingAuthGate`）。二维码一律浅底深点（ML Kit 认不出反色码，暗色与玻璃下底板改用种子色推出的浅色配色，`lan_sync_qr_board.dart`），纠错级别 Q（`LanSyncQrMatrix`）。界面只经 `LanSyncUiController`（`lanSyncControllerProvider`：支持的平台为包着 `LanSyncService` 的 `EngineLanSyncUiController`，iOS 为不联网的 `InertLanSyncUiController`，测试换成 `test/support/fake_lan_sync_controller.dart`），引擎状态与事件到界面模型的换算只在 `lan_sync_engine_mapping.dart` / `lan_sync_engine_events.dart`，禁止界面直接调用引擎；平台门控只经 `AppPlatform.supportsLanSync` / `supportsQrScan`（扫码用 `mobile_scanner` 内置的 ML Kit 模型，不依赖 Google Play 服务，只在 Android）。
