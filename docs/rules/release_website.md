# 应用内更新、官网、打赏与发布流程

> 从 `AGENTS.md` 拆出的专题约束，与 `AGENTS.md` 同等效力（必须 / 禁止 / 例外）。改动本主题的代码前先读本文件；本主题新增或修改的规则写在这里，不写回 `AGENTS.md`。界面规格见 DESIGN.md §5.13 / §5.18；更新说明见 `docs/app_update.md`。

- 必须：应用内更新统一经 `AppUpdateController`（编排与状态）→ `AppUpdateService`（检查 `AppUpdateChecker`、下载与校验 `AppUpdateDownloader`、原生安装 `AppUpdateInstaller`）；界面只有软件更新页 `AppUpdatePage`（设置 → 关于 → 检查更新）与自动检查提示（`AppUpdateAutoChecker` 决定时机 → `runAutoUpdateCheck`）。面向国内网络：版本信息优先读 Release 附件 `jotsy-update.json`，多线路同时请求、取最先成功；回退 GitHub 接口与 `releases/latest` 跳转 + `SHA256SUMS.txt`（读不到校验文件不提示新版本）；下载先测速择优，断线、换线路一律 Range 续传，失速或低速自动切换。线路只在 `AppUpdateSource.builtInSources` 登记（另有用户填写的自定义镜像），禁止在别处拼镜像地址；Android 上禁止以跳转浏览器作为主更新路径（只在没有适配安装包、安装失败时兜底）。桌面（Windows / Linux）只检查、不在应用内下载安装：检查走同一套清单与回退线路，有新版本时“前往下载”经 `AppUpdateController.desktopDownloadUri` 在浏览器里打开本平台安装包（`AppUpdateRelease.desktopAssetFor`：Windows 取安装程序 `.exe`、Linux 取 `.tar.gz`）在首选线路上的下载地址，没有本平台安装包（桌面版之前的版本）时打开发布页面；禁止在桌面显示应用内下载、安装、进度与 ABI。桌面安装包与 APK 写进清单的同一个 `assets` 列表，三种来源（清单、GitHub 接口、校验文件）解析时一律经 `addReleasePackage` 分开存放（`assets` 只有 APK、`desktopAssets` 只有桌面包），禁止让 Android 的挑选拿到桌面包，也禁止发布没有 APK 的清单（桌面版之前的应用只认 `.apk`，没有 APK 会判为无效）。偏好只存于 `AppUpdatePreferences`（单个 JSON 键 `app.update.preferences`，逐字段容错，本机偏好**不随备份导出**），禁止另加零散的更新设置键。更新日志页 `ChangelogPage`（设置 → 关于 → 更新日志）只读随应用打包的 `docs/releases/`（pubspec assets；经 `loadBundledReleaseNotes` 按界面语言选 `<tag>.md` / `<tag>.en.md`、缺失时回落另一种语言，正文经 `cleanReleaseNotes` 清理），不联网、不另建版本目录；卡片常显第一节要点（`splitReleaseHighlights`），其余章节经 `SettingsReveal` 展开，渲染复用 `ReleaseNotesView`，展开状态只在页面内存；本机安装的版本标“当前版本”。安装包只暂存 `getTemporaryDirectory()/app_update/`（`AppUpdateFileProvider` 只暴露该目录），交给系统安装器前必须通过大小 / SHA-256（已知时）与包名 / 签名 / 版本校验，不通过即删除。自动检查只在 Android 与桌面（Windows / Linux）、冷启动与回到前台时进行（桌面的提示主操作为“前往下载”），每 2 小时最多一次（`AppUpdatePreferences.autoCheckInterval`），过程静默、不改动界面状态，可关闭；同一版本每次进程只提示一次，“跳过此版本”只影响自动提示。说明见 docs/app_update.md，视觉规范见 DESIGN.md §5.13。
- 必须：官网在 `docs/`（GitHub Pages，域名见 `docs/CNAME`），保持纯静态 HTML / CSS / 原生 JS 模块，禁止引入构建步骤与外部 CDN（国内访问不稳）；视觉与 app 同源（Material 3 Expressive、无渐变），颜色只用 `--c-*` 色槽，80 种主题色配色在 `docs/assets/data/themes.json`（由 `kColorPaletteFamilies` 经 `appColorSchemeFromSeed` 导出，与应用同一换算；`test/app/theme/site_theme_export_test.dart` 校验两边一致，改色板或配色算法后加 `--dart-define=UPDATE_SITE_THEMES=true` 跑它重新导出；主题色专用的“黑白”不在官网面板里）；中英文写在同一元素（中文为正文，英文在 `data-en` / `data-en-html` / `data-en-<属性>`），改文案两种语言一起改；下载线路与 `AppUpdateSource.builtInSources` 同步；`privacy.html` 是 OAuth 同意屏幕引用的地址，禁止改路径，应用的联网场景或权限变化时同步更新中英两份政策与生效日期。
- 必须：打赏（支持开发者）只在设置 → 关于提供入口，经 `showSupportDeveloperSheet`（展示与挑选）→ `SupportDeveloperController`（执行：经 `ExternalUriLauncher` 拉起支付宝 / 微信、经 `ImageExportService.saveBytesToGallery` 保存收款码）；收款码图片只取 `assets/img/support/`（与 README 共用），支付宝收款码链接与跳转地址只在 `SupportChannel`（`support_channel.dart`）登记，换收款码时图片与链接一起改。打赏不得与任何功能、设置或数据挂钩，禁止弹窗催促或在关于页以外加入口；不联网、不记录任何打赏信息。视觉规范见 DESIGN.md §5.18。
- 必须：发布经 GitHub Release 触发 `release-apk.yml`：tag 必须与 `pubspec.yaml` 的版本一致（`v0.6.0` 或 `v0.6.0+17`），先过同一套 CI 门禁再构建签名分包 APK、Linux 压缩包 `jotsy-<tag>-linux-x64.tar.gz`（顶层 `jotsy/`，含 `linux/packaging/install.sh`）与 Windows 安装程序 `jotsy-<tag>-windows-x64-setup.exe`（`windows/packaging/jotsy.iss`，AppId 禁止更改）/ 便携版 `jotsy-<tag>-windows-x64.zip`，由 publish job 汇总后先上传全部安装包，再上传覆盖全部安装包的 `SHA256SUMS.txt` 与应用内更新清单 `jotsy-update.json`（`tool/write_update_manifest.dart` 生成，最后上传）；写权限只授予 publish job；每个版本须在 `docs/releases/` 写好中英文说明（`<tag>.md` / `<tag>.en.md`），应用内更新页按界面语言显示。
- 必须：Android 安装包同时带 v1 / v2 / v3 签名：`android/app/build.gradle.kts` 的 release 签名配置显式 `enableV1Signing` / `enableV2Signing` / `enableV3Signing = true`（minSdk ≥ 24 时 AGP 默认不签 v1，鸿蒙与部分华为安装器只认 v1 证书，缺了就报“该安装包未包含任何证书”）；`release-apk.yml` 的 `Verify APK signature schemes` 步骤用 `apksigner verify --min-sdk-version 23` 逐个检查（不加该参数时 apksigner 对 minSdk 24 的包不检查 v1），禁止删除这一步或关闭任一签名方案。
- 必须：官网的“累计下载”只统计 `.apk`、不含草稿：优先读 GitHub 接口的实时值，读不到时用 `download-stats.yml` 每小时（及每次 `release-apk.yml` 结束后）以 `jotsy-downloads.json` 上传到最新 Release 的统计（官网经允许跨域的镜像读取）；该 job 只授予 `contents: write`、只用仓库自带令牌，禁止改成提交到仓库或读取其他 secrets；统计口径改动时 `download-stats.yml` 与 `docs/assets/js/download.js` 一起改。
- 例外：装机测试可手动触发 `release-apk.yml` 并勾选 `test-build`（`gh workflow run release-apk.yml --ref <分支> -f test-build=true`）：只有 Android（桌面 job 与 publish 一并跳过）：跳过 CI 门禁、只编译 arm64、不生成更新清单，签名与正式版相同、可覆盖安装，只上传为 workflow artifact（`test-apk-<分支>`）。测试包禁止用于发布；只对已过门禁或仅供本机验证的代码使用，Release 事件始终走完整流程。
